# Подключение EdgeOne MCP к сессии агента (инструкция)

Дата: 2026-11-02
Контекст: агент (SourceCraft Code Assistant) не смог вызвать MCP-инструмент `account_info`
сервера `edgeone-makers-mcp-server`, потому что сервер не подключён к сессии агента.
Диагностика подтвердила: конфиг сервера в `.vscode/msp.json` синтаксически корректен,
но токен не проходит авторизацию в глобальном API EdgeOne (HTTP 567),
а регион API не задан.

---

## 1. Что нужно исправить в `.vscode/msp.json`

Текущее содержимое:

```json
{
  "servers": {
    "edgeone-makers-mcp-server": {
      "timeout": 600,
      "command": "npx",
      "args": ["@edgeone/makers-mcp@latest"],
      "env": {
        "EDGEONE_PAGES_API_TOKEN": "AXYOlYlLOBzvnFtAUOttIMwcmY74brlInxs5fXplk3I=",
        "EDGEONE_PAGES_PROJECT_NAME": "memorial-korpech-crimea"
      }
    }
  }
}
```

### 1.1. Добавить регион API (обязательно)

CLI EdgeOne (`edgeone whoami`) ищет регион в переменной окружения
`EDGEONE_PAGES_API_REGION` (значения: `global` | `china`). Без неё
CLI/сервер делает запрос с `region = undefined` и падает с ошибкой
`Invalid region: undefined`.

Аккаунт EdgeOne Pages этого проекта — глобальный (`ap-singapore`),
поэтому добавить строку:

```json
"EDGEONE_PAGES_API_REGION": "global"
```

### 1.2. Обновить токен (скорее всего обязательно)

Проверка через `edgeone whoami` с этим токеном и регионом `global`
вернула `Request failed with status code 567` — признак невалидного /
просроченного токена. Нужно перевыпустить токен:

1. Открыть консоль EdgeOne Pages: <https://edgeone.ai/document/16276037>
   (Makers console → проект `memorial-korpech-crimea`).
2. Раздел **Account / API Token** — создать новый API Token.
3. Вставить новое значение в `EDGEONE_PAGES_API_TOKEN` в `.vscode/msp.json`.

Проверка токена без MCP (в терминале, из корня проекта):

```cmd
set "EDGEONE_PAGES_API_TOKEN=<НОВЫЙ_ТОКЕН>" && set "EDGEONE_PAGES_API_REGION=global" && edgeone whoami
```

Ожидаемый результат — JSON с данными пользователя (без ошибки 567).

> Важно: при `set "VAR=value" && next` в cmd.exe пробел перед `&&`
> не попадает в значение, поэтому использовать именно кавычки:
> `set "EDGEONE_PAGES_API_TOKEN=..."` (без пробела после `=`).

Файл `.vscode/msp.json` закрыт для чтения агенту правилом `.vscode/*`.
Чтобы агент мог сверять конфиг, добавить исключение:


(После подключения MCP-сервера это исключение можно убрать обратно,
если не хочется показывать токен агенту.)

---

## 3. Что нужно исправить на стороне ХОСТА (подключение MCP к сессии агента)

Конфиг `.vscode/msp.json` описывает сервер, но сам по себе он **не подключает**
сервер к сессии агента. Инструменты (`account_info`, `deploy_folder`) появляются
у агента только если хост-приложение (SourceCraft Code Assistant) при старте
сессии запустит этот MCP-сервер.

Порядок действий:

1. Убедиться, что в настройках агента (настройки режима/модели в SourceCraft
   Code Assistant) указан путь к конфигу MCP-серверов — `.vscode/msp.json`
   (или скопировать блок `servers` в глобальный конфиг MCP агента).
2. Перезапустить сессию агента (новая задача / reload окна), чтобы хост
   поднял сервер `edgeone-makers-mcp-server`.
3. Проверка подключения: в новой сессии агент должен видеть 2 инструмента:
   - `account_info` — информация об аккаунте;
   - `deploy_folder` — деплой папки на EdgeOne Pages.

## 7. Корневая причина «Not logged in» — обновление от 2026-11-02 23:20

С новым токеном и регионом `global` MCP по-прежнему отвечает
`Not logged in`. Прямой запрос к API выявил корневую причину:

| Эндпоинт | Результат |
|---|---|
| `https://pages-api.edgeone.ai/v1` (global) | **HTTP 567** — HTML-страница `AccessDeny / Restricted Access` («The security policy of this website has blocked…») — запрос блокирует WAF/security policy EdgeOne по IP клиента, а не по токену |
| `https://pages-api.cloud.tencent.com/v1` (china) | HTTP 200, `Code 109: The Token usage region is incorrect` — токен валиден, но привязан к глобальному региону |

Выводы:

1. **Токен действителен** — китайский эндпоинт распознал его и сообщил только
   о несоответствии региона.
2. **Токен в msp.json настроен верно** (`mcpServers`, регион `global`).
3. **Проблема — сетевая**: глобальный API `pages-api.edgeone.ai` блокирует
   запросы с текущего IP (security policy / гео-ограничение). User-Agent не
   влияет (проверено). MCP-сервер и CLI в такой ситуации честно отвечают
   «Not logged in».

Варианты решения:

- **A. Прокси/VPN** с IP из разрешённого региона (например, Гонконг/Сингапур).
  Для CLI/MCP задать `HTTPS_PROXY` в окружении (axios в Node читает
  `HTTPS_PROXY`/`HTTP_PROXY` автоматически) — добавить в `env` в `msp.json`,
  например: `"HTTPS_PROXY": "http://127.0.0.1:<порт>"`.
- **B. Китайский аккаунт EdgeOne** (`edgeone.cloud.tencent.com`) — если проект
  может работать на площадке `ap-guangzhou`; тогда создать токен на китайской
  площадке и поставить `"EDGEONE_PAGES_API_REGION": "china"`. VPN не нужен
  (эндпоинт `pages-api.cloud.tencent.com` доступен напрямую).
- **C. Продолжить без EdgeOne Pages API** — деплой/проверки через `tccli`
  (профиль `eo-sub`) и другие каналы; MCP-инструменты `account_info` /
  `deploy_folder` останутся недоступными из этой сети.

Сначала нужно уточнить один момент: **MCP (Model Context Protocol) — это не способ «войти в веб-панель EdgeOne»**, а протокол, позволяющий AI-клиенту (например, Cursor, VS Code, Claude Desktop) вызывать инструменты EdgeOne через локальную команду. Предоставленная вами конфигурация направлена на то, чтобы AI-клиент мог **развёртывать проекты** в EdgeOne Pages, а не открывать для вас интерфейс управления в браузере .

### Оценка вашей конфигурации

Предоставленный вами JSON в целом правильный, но есть несколько моментов, которые следует учесть:

**1. Структура конфигурации**

Формат, который вы используете — `"servers"` — обычно применяется в некоторых клиентах (например, в настройках расширения VS Code), но официальная документация EdgeOne приводит пример с `"mcpServers"` . Если ваш клиент не распознаёт `"servers"`, попробуйте заменить на:

```json
{
  "mcpServers": {
    "edgeone-makers-mcp-server": {
      "timeout": 600,
      "command": "npx",
      "args": ["@edgeone/makers-mcp@latest"],
      "env": {
        "EDGEONE_PAGES_API_TOKEN": "AXYOlYlL888---888rlInxs5fXplk3I=",
        "EDGEONE_PAGES_PROJECT_NAME": "memorial-korpech-crimea"
      }
    }
  }
}
```

**2. Переменные окружения**

- `EDGEONE_PAGES_API_TOKEN`: вы уже заполнили его, этот токен используется для пропуска входа через браузер, MCP будет напрямую использовать его для аутентификации .
- `EDGEONE_PAGES_PROJECT_NAME`: вы указали `memorial-korpech-crimea`, это правильно — MCP развернёт содержимое в этот указанный проект, а не создаст новый .

**3. О регионе**

Вы не указали параметр `--region`, по умолчанию используется **международная версия Tencent Cloud** (International). Если ваш аккаунт EdgeOne относится к **китайской версии Tencent Cloud** (China), необходимо изменить `args` на:
```json
"args": ["@edgeone/makers-mcp@latest", "--region", "china"]
```
В вашей предыдущей консоли был адрес `intl.cloud.tencent.com` (международная версия), поэтому текущая конфигурация без `--region` подходит .

### После настройки

1. **Перезапустите MCP-клиент** (Cursor / VS Code и т.д.), чтобы конфигурация вступила в силу.
2. В диалоговом окне AI попросите его выполнить развёртывание, например: «Разверни текущий проект в EdgeOne Pages» или «Используй EdgeOne MCP для развёртывания папки `dist`».
3. MCP выполнит сборку, загрузку и вернёт публичный URL .

### ⚠️ Важное напоминание

Вы вставили `EDGEONE_PAGES_API_TOKEN` в открытом виде в диалог. **Рекомендую немедленно перевыпустить этот токен** в консоли EdgeOne Pages (удалить старый, создать новый) и обновить конфигурацию. Если этот токен будет раскрыт, другие смогут развертывать или изменять ваши проекты.

Кроме того, MCP в первую очередь используется для **развёртывания и управления** и не может напрямую решить проблему с SSL-сертификатом. Если позже вы захотите продолжить работу над SSL, возможно, потребуется вернуться к решению через API, которое мы обсуждали ранее.

Понял. Ваша цель — использовать MCP для проверки возможности **развёртывания непосредственно из локальной папки проекта** (а не только для загрузки предварительно собранного `dist`). Это выполнимо, но есть один ключевой момент, который нужно скорректировать в вашей конфигурации.

### Ключевая корректировка: какой MCP-сервер использовать

В вашей текущей конфигурации используется `@edgeone/makers-mcp@latest`. Согласно официальной документации, этот сервер в первую очередь ориентирован на «развёртывание полнофункциональных приложений» и может автоматически обрабатывать сборку. Однако, если ваша цель — **явно развернуть локальную папку** (например, указать MCP развернуть корневую директорию проекта или конкретную папку), более прямой выбор — это `edgeone-pages-mcp-fullstack@latest` (или старый `edgeone-pages-mcp`), поскольку он предоставляет инструмент `deploy_folder`, специально предназначенный для развёртывания полных папок проекта.

**Рекомендуемая конфигурация (если вы хотите явно указать папку для развёртывания):**

```json
{
  "mcpServers": {
    "edgeone-pages-mcp-server": {
      "timeout": 600,
      "command": "npx",
      "args": ["edgeone-pages-mcp-fullstack@latest"],
      "env": {
        "EDGEONE_PAGES_API_TOKEN": "ВАШ_ТОКЕН",
        "EDGEONE_PAGES_PROJECT_NAME": "memorial-korpech-crimea"
      }
    }
  }
}
```

Если вы продолжите использовать ваш текущий `@edgeone/makers-mcp`, это тоже возможно, но при вызове в диалоге с AI вам нужно будет более чётко указать: «развернуть локальную папку `dist` в проекте», и AI решит, какой инструмент использовать, на основе описания MCP.

### О вашей текущей конфигурации

- **`EDGEONE_PAGES_PROJECT_NAME`** уже указан, это правильно. Это означает, что развёртывание будет напрямую обновлять ваш существующий проект `memorial-korpech-crimea`, а не создавать новый.
- **`EDGEONE_PAGES_API_TOKEN`** уже указан, это позволяет пропустить вход через браузер и выполнять аутентификацию напрямую через API.
- **`"servers"` vs `"mcpServers"`**: если ваш клиент (например, Cursor, VS Code) не распознаёт конфигурацию, попробуйте заменить внешний ключ на `"mcpServers"` — это соответствует официальным примерам.

### Как проверить

После настройки и перезапуска MCP-клиента попросите AI выполнить примерно следующее: **«Используй EdgeOne MCP для развёртывания локальной папки `dist` в текущем проекте»**. Если AI успешно вызовет инструмент и вернёт URL, это подтвердит, что цепочка развёртывания из локальной среды работает. Это не зависит от проблемы с SSL-сертификатом, с которой вы столкнулись ранее — MCP-развёртывание и привязка сертификата — это две отдельные задачи.
