# LOGIKA-DIAPAZONA.md · четыре оси данных и их словари · v1 · 2026-09-20
Источник истины для карточек = документы (ЦАМО через ОБД/ПМН). Всё остальное —
операторские данные для перекрёстной проверки, не для создания карточек.

## Ось 1. ВРЕМЯ (книги безвозвратных потерь)
- Основное окно: 01.12.1941–19.05.1942 (граница сканирования; Крымский фронт;
  Траппенъягд май-1942).
- Хвост: умер от ран / погиб в плену после 19.05.1942 → флаг tail: true,
  карточка создаётся, не отбрасывается.
- Событие текущего места: перезахоронение __.04.1944 (ВМЦ 82-390/2014) —
  это ось 2, не ось 1.
- death_date вне окна и вне хвоста → код date_out_of_window (сверка вручную),
  не ошибка конвертера.

## Ось 2. ГЕО — три независимых слоя, не смешивать
- L1 смерть/первичное захоронение (МПЗ): высоты 66,3 и 71,3; сёла Кой-Асан /
  Кос-Асан-Русский / Фронтовое; Арма-Эли; Огуз-Тобе; города Феодосия (расстрел
  01.1942, 51 боец), Керчь. Словарь burials: raw → norm + kind: primary.
- L2 призыв: военкоматы материка; словарь loc_map (15 строк + резерв),
  modern — справка в скобке (R-13).
- L3 текущий мемориал: справочник memorials с type (R-18): Корпечь = памятник;
  кандидаты из форума/списков: Батальное, Фронтовое, Приморское, Феодосия,
  Огуз-Тобе, Арма-Эли. Запись — только три поля руками владельца.
- Один топоним вправе жить в разных слоях (Фронтовое: L1 и L3) — слои не
  перекрёстны.

## Ось 3. ЧАСТИ (книги убытия велись писарями частей)
- Иерархия: фронт (СКФ) → армия (44 А) → дивизия (сд) → полк (сп/ап).
- Известно из форума и срезов: СКФ; 44 А; 404 СД; 276 СД; 398 СД (958 ап);
  157 СД (422 ап); 384 сп. Остальное — группировкой v_units, не памятью.
- unit_raw (документ, П1) → unit_norm (units_registry rev3) → unit_id;
  дыра словаря → код unit_gap, выдумка запрещена.
- Ключ среза = {часть × окно × МПЗ}: имена файлов 28-5-2026 уже ему следуют.

## Ось 4. ВЕС ИСТОЧНИКОВ
- Вес 1 (документ): ЦАМО-донесения через ОБД/ПМН — единственные создают карточки.
- Вес 2 (операторские): списки форума (Nazarov, Sanya), txt/csv 28-5-2026 —
  наводки и перекрёст: v_already, счётчики МПЗ (66,3: 404=254, 276=334),
  кандидаты справочника. Карточек из них НЕ создавать.
- Вес 3 (методика): регламент Tatjana4799 (каждая фамилия сверяется по ОБД,
  ПН, Подвиг Народа; проверка плена; письма в военкомат и администрацию) —
  внешнее подтверждение наших П1–П3 и очередей; цитата в docs/01.
- Числа форума = контрольные точки: сходимость числа карточек по МПЗ с
  254/334 — проверка конвертера, не цель.

## Сборка карточки из осей
frontmatter: death_date (ось 1) + burial.history (L1) + conscription (L2) +
memorial_id (L3) + unit-цепочка (ось 3) + sources[] (вес 1).
Коды очередей по осям: date_out_of_window; location_ambiguous; unit_gap;
memorial_unlinked; modern_gap; snippet_gap; stone_check; pow_check.

## Конвейер финального изъятия из хаоса
1. txt/csv 28-5-2026 → sqlite таблица raw_lists (вес 2, отдельно от raw_cards!).
2. Группировки по ключу среза {часть, окно, МПЗ}.
3. Словари burials / units_registry / loc_map / memorials пополняются из
   группировок коммитами data:, приёмка владельцем как данные.
4. Конвертер идёт ТОЛЬКО по весу 1 (parser_mem2026); вес 2 = перекрёст.
5. Тест 50–70 (R-17) → приёмка → полный прогон.
