## 1. РЕГЛАМЕНТНОЕ МЕСТО ДЛЯ ОТВЕТОВ РУКОВОДИТЕЛЯ

### 1.1. Структура папок для документооборота

Рекомендую следующую иерархию в репозитории:

```
memorial-korpech-crimea/
├── docs/
│   ├── tasks/                          # Постановки задач (от вас)
│   │   ├── TASK-0001-apiflash-removal.md
│   │   ├── TASK-0002-domain-binding.md
│   │   └── TASK-0005-csv-converter.md
│   ├── approvals/                      # Утверждённые режимы/решения
│   │   ├── card-type-approval-mode-01.md
│   │   ├── card-type-approval-mode-02.md
│   │   └── card-type-approval-mode-03.md
│   ├── answers/                        # ← РЕГЛАМЕНТНОЕ МЕСТО ДЛЯ ВАШИХ ОТВЕТОВ
│   │   ├── answer-to-mode-03-markdown-capabilities.md
│   │   └── answer-to-TASK-0005-dictionaries.md
│   ├── reports/                        # Отчёты Кодера02
│   │   └── report-from-coder02-TASK-0005.md
│   └── decisions/                      # Фиксация принятых решений
│       └── decision-001-stable-urls.md
├── data/                               # Исходные данные (CSV, словари)
├── scripts/                            # Скрипты-конвертеры
└── src/                                # Код Astro
```

### 1.2. Формат именования файлов ответов

**Шаблон:** `answer-to-[идентификатор-документа]-[краткая-тема].md`

**Примеры:**
- `answer-to-mode-03-markdown-capabilities.md` — ответ на режим 03 по возможностям Markdown
- `answer-to-TASK-0005-dictionaries-structure.md` — ответ по структуре словарей
- `answer-to-coder02-report-2026-09-07.md` — ответ на отчёт Кодера02

**Обязательная шапка файла ответа:**
```markdown
---
type: answer
to: [идентификатор документа, на который отвечаем]
date: 2026-09-07
author: Руководитель IT
status: approved | pending | rejected
---

# Ответ на [название документа]

[Содержание ответа]
```

Это создаёт **аудируемый след** всех решений и позволяет Кодеру02 всегда понимать контекст.

## 2. СПРАВКА ПО ВОЗМОЖНОСТЯМ MARKDOWN В ASTRO (ТЕМА RETYPESET)

### 2.1. Важное уточнение по версиям

Вы упомянули Astro 6.1.5 и 7+. На момент сентября 2026 года:
- **Astro 5.x** — стабильная версия (используется в вашей теме Retypeset)
- **Astro 6.x** — актуальная стабильная
- **Astro 7.x** — находится в разработке/preview

**Важно:** "Волшебство Markdown" в вашем проекте определяется **не версией Astro**, а:
1. Возможностями темы Retypeset (кастомные контейнеры `:::fold`, `:::gallery`, блоки примечаний)
2. Плагинами remark/rehype, которые можно добавить
3. Встроенной поддержкой MDX (если нужна интерактивность)

Ваша тема **уже поддерживает** богатый набор расширений Markdown, и для мемориального проекта этого более чем достаточно.

### 2.2. Полная справка по доступным возможностям

#### А. Блоки примечаний (КРИТИЧЕСКИ ВАЖНО ДЛЯ МЕМОРИАЛА)

**Синтаксис GitHub-стиль:**
```markdown
> [!NOTE]      — нейтральная информация
> [!TIP]       — полезный совет
> [!IMPORTANT] — ключевая информация (для причины гибели, звания)
> [!WARNING]   — требует внимания (для "требуется уточнение")
> [!CAUTION]   — предупреждение о рисках
```

**Синтаксис контейнеров (с кастомным заголовком):**
```markdown
:::note[Пользовательский заголовок]
Текст примечания
:::

:::warning[Внимание: данные требуют проверки]
Текст предупреждения
:::
```

**Применение в мемориале:**
- `> [!IMPORTANT] Причина выбытия` — акцент наcircumstances смерти
- `> [!WARNING] Требуется уточнение` — для недостающих данных
- `:::note[Историческая справка]` — для контекста о подразделении

#### Б. Сворачиваемые разделы (ИДЕАЛЬНО ДЛЯ АРХИВНЫХ ДАННЫХ)

**Синтаксис:**
```markdown
:::fold[Архивные реквизиты источника]
* Тип документа: ЦАМО
* ID: 506255127
* Фонд: (не указан)
:::
```

**Применение:** Архивные данные (фонд, опись, дело) — второстепенная информация для большинства посетителей, но критичная для исследователей. Сворачиваемый блок — идеальное решение.

#### В. Галереи изображений (ДЛЯ ФОТО ПАВШИХ, ЕСЛИ ПОЯВЯТСЯ)

**Синтаксис:**
```markdown
:::gallery
![Портрет бойца](/photos/avdeev-1.jpg)
![Похоронка](/photos/avdeev-2.jpg)
![Место захоронения](/photos/avdeev-3.jpg)
:::
```

**Применение:** Когда родственники пришлют фотографии — галерея позволит показать их компактно и красиво.

#### Г. Таблицы (СТАНДАРТ ДЛЯ АНКЕТЫ)

**Синтаксис:**
```markdown
| Характеристика | Данные |
| :--- | :--- |
| **ФИО** | Авдеев Григорий Иосифович |
| **Год рождения** | — |
```

#### Д. HTML-теги (ДЛЯ ТОЧНОГО ФОРМАТИРОВАНИЯ)

Поддерживаются:
- `<sup>` — верхний индекс (например, для номеров армий: 3<sup>-й</sup> Белорусский фронт)
- `<sub>` — нижний индекс
- `<mark>` — выделение текст
