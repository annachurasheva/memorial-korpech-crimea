# РЕГЛАМЕНТ ФОРМИРОВАНИЯ КАРТОЧКИ ПЕРСОНЫ (РЕЖИМ 02)

**Проект:** Memorial Korpech Crimea
**Стек:** Astro (SSG) / EdgeOne Pages / Node.js
**Цель:** Создание уважительного, человеко-ориентированного представления данных с возможностью интерактива (комментарии) и навигации по связям (сослуживцы, места захоронений).

---

## 1. ТЕХНИЧЕСКИЕ ОГРАНИЧЕНИЯ И ИНСТРУМЕНТЫ

1. **Язык скрипта-конвертера:** Строго **Node.js** (`.mjs` или `.js`). Это обеспечивает нативную совместимость с экосистемой Astro, `package.json` и процессом сборки на EdgeOne Pages. Использование Python исключено.
2. **Неизменность ядра:** Структура темы Retypeset (Astro-компоненты, роутинг) не модифицируется. Вся кастомизация достигается за счет грамотного формирования Markdown-файлов и использования встроенных функций темы (Front Matter, теги, блоки примечаний).

---

## 2. ФИЛОСОФИЯ "ЖИВОЙ ПАМЯТИ" И КОММЕНТАРИИ

Карточка персоны является **самостоятельной, полноценной страницей**. Под ней обязательно должен быть развернут фрейм комментариев (через встроенную в тему поддержку, например, Giscus или Waline).

**Требование к генерации:**
В Front Matter каждой сгенерированной карточки должно быть явно указано разрешение на комментарии (если это не глобальная настройка), чтобы посетители (родственники, односельчане, исследователи) могли оставить верифицированную память: *"Это мой прадедушка"*, *"Мы установили ему памятник в селе..."*.

---

## 3. ОБРАБОТКА И ПОДМЕНА ДАННЫХ (Node.js Скрипт)

Скрипт при чтении CSV обязан применять правила трансформации "на лету":

### 3.1. Воинские звания
Использование словаря подмены (`ranks_dict.json`). Любые сокращения (`ст. лейтенант`, `ст.л.`, `ст. лей.`) заменяются на полное, корректное написание: **Старший лейтенант**.
*Реализация в Markdown:* Выводится как обычный текст в таблице или, при наличии ресурсов, как стилизованный бейдж/иконка.

### 3.2. Воинские части (Расшифровка шифрограмм)
Использование словаря частей (`units_dict.json`).
*Пример:* `422 ап 157 сд` → **422-й артиллерийский полк 157-й стрелковой Неманской дивизии 5-й армии 3-го Белорусского фронта**.
*Если совпадение не найдено:* Скрипт оставляет исходное значение, но добавляет в конец файла HTML-комментарий `<!-- ВНИМАНИЕ: Требуется ручная проверка сокращения: [значение] -->` для последующего пополнения словаря.

### 3.3. Дата рождения
Алгоритм нормализации даты:
- Если поле пустое → выводить `—`.
- Если указана полная дата (например, `15.05.1920` или `1920-05-15`) → извлекать и выводить **только год** (`1920`), так как полные даты часто отсутствуют или неточны в архивах ЦАМО.
- Если указан только год → выводить как есть.

## 4. САЙТОВЫЕ СВЯЗКИ (НАВИГАЦИЯ И ГРУППИРОВКА)

Для создания "паутины памяти" и связи карточек между собой используется **двухуровневая система**, полностью опирающаяся на возможности Astro:

### Уровень 1: Теги (Автоматические страницы списков)
В Front Matter каждой карточки скрипт автоматически прописывает специализированные теги. Тема Retypeset автоматически сгенерирует по ним страницы со списками персон.
```yaml
tags:
  - unit: 422-й артиллерийский полк 157-й сд
  - burial: Крымская АССР, Ленинский р-н, выс. 66,3
  - rank: Старший лейтенант
```
*Результат:* Пользователь может кликнуть на тег "422-й артиллерийский полк..." и увидеть список всех бойцов этого подразделения, представленных на сайте.

### Уровень 2: Явные перекрестные ссылки в теле карточки (Блок "Сослуживцы")
Node.js скрипт работает в два прохода (или держит данные в памяти):
1. Собирает индекс: какая `abbrlink` (уникальный ID) к какой `warunit` принадлежит.
2. При генерации карточки Ивана Иванова, скрипт находит 2-3 других бойцов из того же подразделения и добавляет в конец Markdown-файла блок:

```markdown
---
## Сослуживцы по подразделению

* [Петров Петр Петрович](/posts/petrov-petr-506255128/)
* [Сидоров Сидор Сидорович](/posts/sidorov-sidor-506255129/)

> *Нажмите на имя, чтобы перейти к карточке сослуживца и оставить память.*
```

## 6. СЛЕДУЮЩИЕ ШАГИ ДЛЯ РУКОВОДИТЕЛЯ

1. **Утвердить данный документ** как `card-type-approval-mode-02.md`.
2. **Подготовить словари:** Начать заполнять файлы `ranks_dict.json` и `units_dict.json` (можно начать с 10-20 самых частых значений из вашего CSV для теста).
3. **Дать команду Кодер02** на написание Node.js скрипта-конвертера строго по этому ТЗ, включая двухпроходную логику для блока "Сослуживцы".

### 👨‍💼 Комментарий для вас (вне документа):
Такой подход (Теги + Явные ссылки внизу страницы) является золотым стандартом для SSG-сайтов. Он не требует создания тысяч отдельных страниц для "мест захоронений" (что раздуло бы сайт), но при этом дает пользователю мощные инструменты для исследования: он видит список сослуживцев прямо в карточке и может кликнуть на тег, чтобы увидеть всех, кто лежит в той же братской могиле.
