## 2. РЕГЛАМЕНТНОЕ МЕСТО ДЛЯ ДАННЫХ (Лучшие практики IT-индустрии)

Для проекта мемориала рекомендуется следующая структура:

```
memorial-korpech-crimea/
├── data/                          # ← РЕГЛАМЕНТНОЕ МЕСТО ДЛЯ ДАННЫХ
│   ├── csv/                       # Исходные CSV-файлы
│   │   ├── cvs-001.csv
│   │   ├── cvs-002.csv
│   │   └── ... (до cvs-231.csv)
│   ├── dictionaries/              # Словари подмены (JSON)
│   │   ├── ranks_dict.json        # Звания
│   │   ├── units_dict.json        # Войсковые части
│   │   ├── burials_primary.json   # Первичные захоронения
│   │   └── burials_current.json   # Текущие захоронения
│   └── settlements/               # Малые поселения (мемориалы сельского уровня)
│       └── settlements_list.json
├── scripts/                       # Скрипты-конвертеры
│   └── csv-to-markdown.mjs        # Node.js скрипт
├── src/
│   └── content/
│       └── posts/
│           └── memorial/          # Сгенерированные карточки персон
└── docs/
    ├── card-type-approval-mode-01.md
    ├── card-type-approval-mode-02.md
    └── card-type-approval-mode-03.md
```

**Обоснование:**
- Папка `data/` находится **вне** `src/`, что предотвращает случайную публикацию исходных CSV в production build
- Словари в формате JSON легко редактируются вручную и версионируются через Git
- Скрипты в `scripts/` — стандартная практика для Node.js проектов
-.Generated контент попадает в `src/content/posts/memorial/`, откуда Astro его подхватывает

## Требования к скрипту

### 1. Чтение CSV
- Использовать библиотеку `csv-parse` (или аналог)
- Обрабатывать все файлы `cvs-*.csv` из папки `data/csv/`
- Корректно обрабатывать кавычки и спецсимволы

### 2. Применение словарей подмены
- `rank` → искать в `ranks_dict.json`, если не найдено — оставлять как есть + добавлять HTML-комментарий `<!-- ПРОВЕРИТЬ: [значение] -->`
- `warunit` → искать в `units_dict.json`, аналогично
- `date_birth` → извлекать только год (если полная дата)

### 3. Генерация Front Matter
```yaml
---
title: '[last_name] [first_name] [middle_name]'
published: [Дата из CSV]
description: '[rank]. [cause_of_death].'
tags:
  - rank: [rank]
  - unit: [warunit расширенный]
  - burial-primary: [primary_burial транслитерированный]
abbrlink: '[document_type.toLowerCase()]-[document_id]'
lang: ru
---
```

### 4. Генерация тела Markdown
Использовать структуру из документа `docs/card-type-approval-mode-03.md`:
- Таблица "Анкета персоны"
- Блок `> [!IMPORTANT]` для причины выбытия
- Блок `> [!IMPORTANT]` для первичного захоронения + ссылка на тег
- Блок `> [!WARNING]` или `> [!NOTE]` для текущего захоронения
- Сворачиваемый блок `:::fold[Архивные реквизиты]`
- Ссылка на первоисточник

### 5. Блок "Сослуживцы" (двухпроходная логика)
**Первый проход:** Собрать индекс `{warunit: [array of {title, abbrlink}]}`
**Второй проход:** Для каждой карточки добавить блок:
```markdown
## Сослуживцы

* [ФИО](/posts/[abbrlink]/)
* [ФИО](/posts/[abbrlink]/)
```

### 6. Обработка пустых значений
- Если поле пустое → выводить `—` (тире)
- Если `primary_burial` пустое → не генерировать блок "Первичное захоронение"
