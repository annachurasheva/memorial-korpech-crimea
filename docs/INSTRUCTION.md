## Как пользоваться документом

Это ежедневная памятка ПОЛЬЗОВАТЕЛЯ (человека).

Фундамент — в других документах:

- РЕГЛАМЕНТ_РАБОТ.md — процесс (этапы, сборки, PASS/FAIL);
- docs/architecture.md — архитектура и контракты (карточка v2);
- QWEN.md — правила КОДЕРА (агент не проектирует, только исполняет).

При противоречии сила такая: решение проектировщика (чат + docs/tasks) > этот документ > всё остальное.

Чат — для обсуждений. Репозиторий — для решений. Важное из чата обязано оказаться в репо.

## Роли и каналы

- Проектировщик (дизайн-чат): задания, решения, верификация raw на GitHub, приёмка хэшей.
- Кодер02 (coder.qwen.ai / SourceCraft): исполняет задачи, выдаёт файлы отдельными код-блоками; сам НЕ коммитит.
- Пользователь: применяет файлы в VS Code, Build, коммит, пуш, тест в Edge, передача хэшей, вердикт PASS/FAIL.

## Задачи и статусы

Задачи живут в docs/tasks/TASK-NNNN.md. Один файл = одна задача. Нумерация последовательная, без перенумеровок.

Статусы задачи: NEW → IN WORK → DONE.

Кодер работает только из задач со статусом NEW.

DONE — только после хэша коммита пользователя по этой задаче.

«Сборка зелёная у Кодера» — НЕ приёмка. Приёмка = файлы в репо пользователя + верификация проектировщиком.

## 📋 ИНСТРУКЦИЯ ПО КОММИТАМ (conventional commits)

Формат: `<тип>: <короткое описание>` + тело коммита (опционально).

### Типы коммитов для этого проекта

| Тип | Когда применять | Пример |
|-----|----------------|--------|
| `docs` | Изменения в документации (QWEN.md, ADR, README, инструкции) | `docs: поправки к ADR-02 (ID карточки, гравировка)` |
| `feat` | Новая функциональность (новые страницы, компоненты) | `feat: компонент CardFull.astro` |
| `fix` | Исправление бага | `fix: падение сборки при пустом unit_id` |
| `refactor` | Переписывание кода без изменения функциональности | `refactor: упрощение логики конвертера` |
| `data` | Изменения в данных (CSV, словари, JSON, MD-карточки) | `data: первые 50 карточек в src/content/fallen/` |
| `chore` | Служебные изменения (зависимости, конфиги, не влияющие на функционал) | `chore: обновление pnpm-lock.yaml` |
| `style` | Форматирование (пробелы, точки с запятой, отступы) | `style: форматирование astro.config.ts` |
| `test` | Добавление тестов | `test: тесты конвертера CSV→MD` |
| `build` | Изменения в системе сборки | `build: переход на Astro 6.2` |
| `ci` | Изменения в CI/CD | `ci: workflow для EdgeOne` |

## Передача кода без порчи

Не копировать код из рендер-вью чата: markdown съедает подчёркивания. Копировать из код-блоков raw или из файла в VS Code.

Файл = ровно одна копия кода. Запрещены: строки «修改后», пути файлов текстом, вторые копии, дописанные в конец.

Селекторы и regex с «_» — в коде только через String.fromCharCode(95).

Самопроверка после применения:

- Get-ChildItem dashboard\src, EdgeExtension -Recurse | Select-String '修改后' → 0;
- панель Problems (Ctrl+Shift+M) → 0 ошибок;
- `npm run build` (внутри ) → проходит.

оба значения — в отчёт.

## Взаимодействие с Delta-02 (AI-консультант)

### Постановка задач

1. Создайте файл в `docs/tasks/TASK-XXXX-[тема].md`
2. Опишите задачу чётко, без двусмысленностей
3. Укажите приоритет и дедлайн (если есть)

### Получение ответа

1. Скопируйте полный ответ Delta-02
2. Сохраните в `docs/answers/answer-to-TASK-XXXX-[дата].md`
3. Добавьте свои заметки в конец файла

### Сверка

1. Перед коммитом: `git log -1 --oneline`
2. Отправьте хеш Delta-02 для подтверждения
3. Получите OK → делайте коммит

### Теги коммитов

- `feat:` — новая функциональность
- `fix:` — исправление ошибок
- `docs:` — документация
- `data:` — загрузка данных (CSV, словари)
- `chore:` — рутинные задачи

## Запуск окружения

1. Edge с чистым профилем: `scripts/run-edge-vk-test.ps1` (или RunEdgeCdp.ps1 — с портом 9222 для CDP). Пути к Edge и профилю зашиты в начале файла — править там. Если Windows запрещает запуск: Set-ExecutionPolicy -Scope Process Bypass (один раз, для терминала).
2. Расширение: edge://extensions → «Режим разработчика» → «Загрузить распакованное расширение» → папка dist/ (после Build — кнопка Reload ⟳ на карточке).
3. Дашборд: cd dashboard → npm install (один раз) → npm run dev (http://localhost:5180) либо npm run build + npm run preview.
