### ФАЙЛ 1: Для подгруппы «Историки-архивисты»
**Путь для сохранения:** `docs/school/volunteers/HISTORIAN_GUIDE.md`

```markdown
# Руководство волонтёра: Историк-архивист

**Роль в проекте:** Пользователь (смыслы, вердикты, работа с данными).
**Цель:** Обеспечить историческую точность и уважительное представление данных о павших воинах.

## 1. Твои основные задачи
- **Расшифровка сокращений:** Поиск полных названий воинских частей и званий по архивным справочникам.
- **Работа со словарями:** Добавление найденных соответствий в файлы `data/dictionaries/`.
- **Верификация:** Проверка сгенерированных карточек на наличие фактических ошибок (опечатки в ФИО, датах).

## 2. Как работать со словарями (JSON)
Словари находятся в папке `data/dictionaries/`. Открывай их в любом текстовом редакторе (Блокнот, VS Code).

**Пример (`ranks_dict.json`):**
```json
{
  "ст. лейтенант": "Старший лейтенант",
  "мл. сержант": "Младший сержант"
}
```
**Правило:** Слева — точное написание из CSV (как в архиве), справа — правильное полное написание для сайта. Сохраняй файл в формате UTF-8.

## 3. Этика работы с данными
- Мы работаем с памятью о реальных людях. Любое изменение должно быть обосновано архивным документом.
- Если данные противоречивы, не удаляй их. Добавь комментарий в лог или обсуди с куратором.
- При поиске родственников в соцсетях используй только уважительный тон, представляйся волонтёром школьного музея.

## 4. Чек-лист перед сдачей работы
- [ ] Новые записи добавлены в словари.
- [ ] Файлы словарей сохранены в формате `.json` без синтаксических ошибок (проверь запятые и кавычки).
- [ ] Сообщил IT-куратору, что данные готовы к повторной генерации.
```

### ФАЙЛ 2: Для подгруппы «IT-направление» (факультатив)
**Путь для сохранения:** `docs/school/volunteers/IT_GUIDE.md`

```markdown
# Руководство волонтёра: IT-куратор (факультатив)

**Роль в проекте:** Проектировщик / Кодер (работа с кодом, схемами, запуск инструментов).
**Цель:** Освоить базовые инструменты IT-индустрии (Git, Node.js, CLI) и обеспечить техническую работу конвертера данных.

## 1. Твои основные задачи
- Поддержка рабочего окружения (VS Code, терминал).
- Запуск скрипта конвертации `csv-to-markdown.mjs`.
- Анализ логов ошибок и передача их историкам-архивистам.
- Фиксация изменений в Git (commit & push).

## 2. Базовый рабочий цикл (Workflow)
Выполняй эти шаги в терминале VS Code в папке проекта:

1. **Получить свежие данные:**
   ```bash
   git pull origin qwen-memorial-coder
   ```
2. **Установить зависимости (если проект скачан впервые):**
   ```bash
   pnpm install
   ```
3. **Запустить конвертер:**
   ```bash
   node scripts/csv-to-markdown.mjs
   ```
4. **Проверить результат:**
   - Открой файл `scripts/logs/errors.json`. Если он пуст или содержит только знакомые ошибки — всё отлично.
   - Если есть новые ошибки, передай список историкам-архивистам для пополнения словарей.
5. **Зафиксировать изменения:**
   ```bash
   git add data/dictionaries/ src/content/posts/memorial/
   git commit -m "chore: обновление словарей и генерация карточек [TASK-XXX]"
   git push origin qwen-memorial-coder
   ```

## 3. Правила работы с Git (Conventional Commits)
Используй строгий формат сообщений коммитов. Примеры:
- `feat: добавлен словарь для 157-й стрелковой дивизии [TASK-005]`
- `fix: исправлена опечатка в abbrlink для документа 506255127 [TASK-006]`
- `docs: обновлена инструкция для волонтёров [TASK-007]`

**Запрещено:** Смешивать `fix` и `refactor` в одном коммите. Делай маленькие, понятные изменения.

## 4. Чек-лист перед сдачей работы
- [ ] Скрипт отработал без критических ошибок (код завершения 0).
- [ ] Файлы `.md` появились в `src/content/posts/memorial/`.
- [ ] Коммит содержит только логически связанные изменения.
- [ ] Push в репозиторий выполнен успешно.
```
