## 1. Структура проекта

**Архитектурные решения зафиксированы в [ADR-02: Архитектура Второго Слоя](docs/decisions/02-memorial-architecture.md).**

### Технологический стек

- **Ядро:** Astro 6.1.5 (SSG)
- **Хостинг:** EdgeOne Pages (статика, доступ во всех локациях)
- **Пакетный менеджер:** pnpm 10.33.0
- **Тема:** radishzzz/astro-theme-retypeset (donor)

### Два слоя контента

#### Первый Слой (смысл, статьи, законы)

- **Коллекция:** `src/content/posts/` (MD-файлы)
- **Роуты:** `/`, `/about`, `/posts/[slug]`
- **RSS:** `/atom.xml` (для Дзен)
- **Комментарии:** Giscus (тестирован, применим)

#### Второй Слой (мемориал)

- **Коллекция:** `src/content/fallen/` (MD-файлы, frontmatter с полной схемой)
- **Роуты:** `/memorial`, `/memorial/card/[slug]`, `/memorials/`
- **RSS:** `/memorial/rss.xml` (транзит Дзен → ОК → сельские библиотеки)
- **Комментарии:** Giscus

### Структура данных

#### Источник истины

- **Сырые данные:** `data/csv/YYYY-MM-DD/parser_mem2026.csv`
- **Словари подмены:** `data/dictionaries/` (ranks, units, burials, locations)
- **Логи:** `scripts/logs/` (errors.json, processing.log, clarify.queue.json)

#### Конвейер обработки

```text
CSV → csv-to-markdown.mjs → src/content/fallen/*.md
```

**Правила:**

- Конвертер создаёт только новые карточки, существующие не перезаписывает;
- Админ (Anna-Ch) имеет право править карточки;
- Пустой `current_burial` → задача в `clarify.queue.json`.

#### Структура карточки (frontmatter)

```yaml
id: '551267195' # document_id ЦАМО (вечный)
slug: petrov-v-v-551267195 # транслитерация ФИО + document_id
status: processed # inbox | processed | rejected
description: Герой Петров В.В. Мемориал павших...

person: {last_name, first_name, middle_name, birth_year, death_date, cause}
service: {rank_raw, rank_norm, unit_raw, unit_norm, unit_id}
burial: {primary_norm, current_norm, current_status}
relatives: [{name, address, relationship}]
identification: {status, source}
memorialization: {status, type, location, plate_number, engraved}
awards: [] # появляется только если что-то внесено
photo: [/photos/551267195/photo1.jpg]
sources: [{org, url}]
```

Детали: ADR-02, раздел "Структура карточки".

### Справочник мемориалов

- **Коллекция:** `src/content/memorials/`
- **Роут:** `/memorials/`
- **Пополнение:** Anna-Ch вручную (три поля)

### Компоненты UI

- `CardFull.astro` — полная карточка
- `CardSummary.astro` — карточка в списке
- `SearchBar.astro` — поиск
- `Filters.astro` — фильтры (вилка 01.12.1941–19.05.1942)
- `ComradesList.astro` — сослуживцы (динамически по unit_id + вилка)
- `CommentsBlock.astro` — Giscus + бронь первого слова

### Временная вилка

01.12.1941–19.05.1942 (граница на уровне сканирования, не фильтр UI).

### Транзит контента

- Дзен: RSS → 500 карточек за раз;
- ОК: Дзен → одноимённая группа;
- Сельские библиотеки: ОК → поселковые доски памяти.

### Миссия проекта

- 226 000 павших за 5 месяцев на Крымском перешейке;
- 3 100 в Корпечь (сейчас "неизвестные", но по документам — известны);
- Каждый павший — Герой по умолчанию;
- Переиздание Мемориала (гравировка на камне);
- Приглашение родственников на открытие (поездка за счёт РФ).

## 5. GitHub и контроль изменений

GitHub контролируется только **Anna-Ch**.

### Принцип

Схема:

```text
Anna-Ch
→ Дельта
→ Кодер
→ diff
→ Дельта / ревизия
→ Anna-Ch
→ ручной перенос изменений
→ commit
→ hash
```

### Запрещено

Дельта и Кодер не должны считать, что имеют право:

* самостоятельно делать commit;
* самостоятельно менять историю Git;
* самостоятельно выполнять merge;
* самостоятельно публиковать изменения в основной ветке;
* считать diff автоматически принятым;
* подменять решение Anna-Ch.

### История изменений

Каждый принятый набор изменений должен иметь:

* понятный commit;
* hash;
* связь с задачей или изменением, ради которого он был сделан.

## 6. Формат работы с Кодером

Основной формат передачи результата от Кодера:

**DIFF**

Кодер должен отдавать изменения как diff, а не просто описывать словами, что было сделано.

Предпочтительный формат:

```diff
--- a/path/to/file
+++ b/path/to/file
@@
- старый код
+ новый код
```

Если требуется создать новый файл, diff должен явно показывать создание файла.

Если требуется удалить файл, diff должен явно показывать его удаление.

---

## 7. Правило минимального изменения

При выполнении задачи Кодер должен изменять только то, что необходимо для поставленной задачи.

Не следует:

* проводить самостоятельный рефакторинг;
* менять стили проекта без задания;
* обновлять зависимости без необходимости;
* менять архитектуру;
* переименовывать файлы "для красоты";
* форматировать весь проект;
* исправлять несвязанные проблемы;
* добавлять новые библиотеки без согласования.

Если Кодер обнаруживает проблему, не относящуюся непосредственно к текущей задаче, он сообщает о ней отдельно.

## 9. Отношение к исходному шаблону

Нельзя автоматически считать, что существующая архитектура шаблона должна быть полностью переделана.

1. что сейчас делает существующая архитектура;

4. какие файлы будут затронуты;

6. можно ли решить задачу меньшим изменением.

## 11. Разделение "решение" и "исполнение"

Важно различать два уровня.

### Уровень 1 — проектирование

Дельта определяет:

* что нужно сделать;
* зачем это нужно;
* где это должно находиться;
* какие ограничения существуют;
* каким должен быть ожидаемый результат.

### Уровень 2 — исполнение

Кодер определяет конкретную реализацию в рамках поставленной задачи и возвращает diff.

Если реализация требует изменения архитектурного решения, вопрос возвращается на уровень проектирования.

## 12. Проверка результата

До передачи результата Anna-Ch Дельта должна проверить:

* соответствует ли diff поставленной задаче;
* не появились ли лишние изменения;
* не изменена ли архитектура без разрешения;
* не добавлены ли ненужные зависимости;
* не затронуты ли несвязанные файлы;
* соответствует ли результат существующей структуре проекта.

Если проверка невозможна без запуска проекта или тестов, это должно быть явно указано.

## 19. Правило "Source of Truth" (Источник истины)

Для каждого слоя проекта должен быть явно определен единственный источник данных.

* **Первый слой (Публикации)**: Источником истины являются Markdown/MDX файлы в директории `src/content/posts/`. Ручное редактирование этих файлов разрешено и является основным способом управления контентом.
* **Второй слой (Карточки)**: Источником истины являются сырые данные (CSV/JSON) в директории `data/`. Фронтенд генерируется исключительно скриптами. Ручная правка сгенерированных страниц запрещена.
