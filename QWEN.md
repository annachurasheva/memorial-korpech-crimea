# 5. Формат работы с Кодером

Основной формат передачи результата от Кодера:

**DIFF**

Кодер должен отдавать изменения как diff, а не просто описывать словами, что было сделано.

Предпочтительный формат:

```diff
--- a/path/to/file
+++ b/path/to/file
@@
- старый код
+ новый код
```

Если требуется создать новый файл, diff должен явно показывать создание файла.

Если требуется удалить файл, diff должен явно показывать его удаление.

# 6. Правило минимального изменения

При выполнении задачи Кодер должен изменять только то, что необходимо для поставленной задачи.

Не следует:

* проводить самостоятельный рефакторинг;
* менять стили проекта без задания;
* обновлять зависимости без необходимости;
* менять архитектуру;
* переименовывать файлы "для красоты";
* форматировать весь проект;
* исправлять несвязанные проблемы;
* добавлять новые библиотеки без согласования.

Если Кодер обнаруживает проблему, не относящуюся непосредственно к текущей задаче, он сообщает о ней отдельно.

Дельта определяет:
